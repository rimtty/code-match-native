# スキャナー照明の実機確認

対象は公式Inateck Android SDK 2.0.0を使うAndroidアプリです（実機確認時は非配付`scannerPoc`、2026-09-05の#56以降は`release`に同梱）。2026-09-05のIssue #57で、下記「確認手順」の未実施分は打ち切りとしました。打ち切りは検証成功を意味しません。

## 実機確認記録（2026-09-05）

- Pixel 7＋使用中スキャナーで、ユーザーが接続後の手動OFFで消灯、ONで点灯することを確認。
- 接続直後はOFFに見えるのに点灯していたとの報告あり。未確認・適用中・失敗もOFF形状のスイッチを表示していたため、未確認／適用中は進捗表示、失敗はOFF再適用ボタン、確認済みのみスイッチ表示へ修正。
- 表示修正版3a8df21で、ユーザーが確認中表示からOFFへ遷移し、スイッチを操作せずトリガーを引いても消灯を維持することを確認。初期OFFおよび手動ON/OFFの物理動作は受入済み。QR→Code128、背景・切断競合の今回の受入結果は未取得。
- ユーザーより、GATT経由の照明OFFはスキャナー本体に保存されて残るとの報告。アプリは切断時に照明の元値を復元しない。コード種類のセッション設定復元とは別の設定であり、設定画面でも保存・非復元を明記する。電源断後の保持期間や他機種の挙動まで検証済みとはしない。

設定画面の照明OFFは常時消灯、ONは読取中点灯です。接続ごとにOFFを適用し、SDKで再取得した値が一致してから確定表示します。SDKのinventoryにある`lighting_lamp_control`のareaを保持します。一般APIのflag 1003をareaへ置き換える推測はしません。

確認手順（1〜3はPixel 7で受入済み、4〜6は対象外・打ち切り）:

1. 接続後、照明設定の確認が終わりOFFになることを確認する。
2. ONへ変更し、トリガー中に点灯することを確認する。
3. OFFへ変更し、トリガー中にも消灯することを確認する。
4. QR→Code 128で照合し、照明変更後も工程と件数が正しいことを確認する。
5. 設定変更中に背景へ移動し、復帰後に設定失敗や工程消失がないことを確認する。
6. 設定変更中の手動切断、スキャナー電源OFF、再接続を確認する。古い接続の成功表示が新しい接続に混ざらず、再接続ではOFFへ戻ることを確認する。

自動検証はコマンドのidentity保持・値の確認・未対応拒否、保留要求の最新化と順序、および設定画面の操作通知・変更中の未確定表示・確認後ON表示・切断時無効化を対象にします。実SDK通信中の通知の取りこぼし、タイムアウト時のコード種類設定の完全復元は未検証です。照明の物理動作は上記の実機確認範囲で受入済みです。

既知の受信制約: 現行通知bridgeはSDKタスク実行中のFF01通知をSDKの設定応答処理へ渡し、途中のスキャンバッファをクリアします。そのため照明変更中の読み取りを保持する保証はありません。通常の確認では設定確定後にトリガーを引きます。同時読み取り対応には、SDK応答とスキャンのフレーム識別・分割通知の混在を検証する追加実装が必要です。

読取時間延長、周辺コードの狙い撃ち設定、BLE受信の追加改善はIssue #59で扱います。この照明変更だけで完了とは扱いません。

## 読取時間の調査境界

公式一般設定表（https://docs.inateck.com/scanner-sdk-en/ble/desktop_setting_list/ ）では、flag 1023は自動消灯モード（1006 = 2）の読取時間で、5秒は25です。一方1022は連続スキャンの間隔であり、読取時間延長の代用にはしません。これらのflagをAndroid SDK 2.0.0のareaへ転用せず、実機の対応項目とSDKの表現を確認してから適用します。照明テストのビルドは読取モード・読取時間を変更しません。

周辺コードの誤読とBLE取りこぼしは別の問題です。キャッシュ自動転送を有効にするだけでは、過去のコードが現在の工程へ入る危険があるため対策完了としません。実機確認では、意図したQR→Code128の順序に加え、設定変更中の読み取りと再接続後の遅延通知を区別して確認します。
